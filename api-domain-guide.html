Before you start

Render is an alternative to Vercel. Its Hobby plan includes custom domains for web services. For a non-root hostname, Render's DNS instructions use a CNAME to the service's .onrender.com address. You must be able to edit DNS records for the RWD.2BD.NET zone in FreeDomain.one.

Render's documented process is to add the custom hostname to the service, create its DNS record at your DNS provider, then verify it in Render. It issues and renews HTTPS certificates after verification. Render custom-domain docs ↗

This setup uses render.yaml at the repository root. It starts the existing Node server, which dispatches the REWIND API routes and serves static files.

1 · Create the Render web service

1

Create from the Blueprint

Sign in to Render, choose New → Blueprint, connect GitHub, and select flare-OS/rwd-website. Render reads the root render.yaml file and prepares the REWIND web service.

2

Use the repository root and enter secrets

Set the Blueprint root to the folder containing render.yaml, package.json, and server.js—the repository root. During Blueprint creation, provide the requested private values: DATABASE_URL and the S3 credentials. Never put these values in render.yaml.

3

Create and deploy

Approve the Blueprint and wait for its first deploy to finish. Render will show a service URL such as rewind-api-xxxx.onrender.com. Keep that URL handy; Render uses it as the CNAME target. Render's official Blueprint guide ↗ explains how Blueprint creation works.

Manual setup option

If you prefer not to use a Blueprint, create New → Web Service from the same repo and set build command npm ci, start command npm start, and health check path /api/health. Choose the Free plan for testing. Add the environment values from the next section manually.

2 · Add the environment variables

Open the service's Environment page. The Render Blueprint marks secret values as private inputs; add the production values there. Use:

KEYVALUE
NODE_ENVproduction (the Blueprint sets this)
DATABASE_URLYour Neon PostgreSQL connection string
CORS_ORIGINShttps://rwd.2bd.net,https://flare-os.github.io
API_PUBLIC_URLhttps://api.rwd.2bd.net
S3_ENDPOINTYour S3-compatible object-storage endpoint
S3_REGIONYour bucket region
S3_BUCKETYour bucket name
S3_ACCESS_KEY_IDPrivate bucket access key
S3_SECRET_ACCESS_KEYPrivate bucket secret key
S3_PUBLIC_BASE_URLOptional public base URL for approved bucket objects

Render usually redeploys when environment variables change; use Manual Deploy → Deploy latest commit if it does not.

Keep secrets in Render's Environment settings. Do not commit `.env`, database credentials, or bucket keys to GitHub.

3 · Add the custom hostname in Render

  1. Open the service's Settings page.
  2. Find Custom Domains, choose Add Custom Domain.
  3. Enter api.rwd.2bd.net and save.
  4. Render shows the DNS record it expects. Keep this page open for verification.

4 · Add the CNAME in FreeDomain.one

Open FreeDomain.one's DNS page for the RWD.2BD.NET zone—the page that shows Host Records and Alias Records. In Alias Records (CNAME), add this record:

FREEDOMAIN.ONE FIELDVALUE
Alias / CNAME Recordapi.rwd.2bd.net. (or api if the panel appends the zone)
Alias to HostThe exact .onrender.com target shown in Render
TTLLeave the default, such as 08:00

Save the record, return to Render → Settings → Custom Domains, and press Verify. Do not include https:// in the CNAME target.

Only add the api record. Leave the existing rwd.2bd.net and www records alone so the GitHub Pages website keeps its current DNS. If there is an AAAA record specifically for api, remove that conflicting API-host record; do not change records for the website hostname.

Render states that non-root hostnames should use a CNAME to the service's Render subdomain. DNS can take time to propagate. Render instructions for other DNS providers ↗

If FreeDomain.one won't let you create the api record, the Render service still has its own .onrender.com address. You can use that API hostname by putting it in assets/config.js as apiBase, then pushing the frontend update.

5 · Prepare Neon and the upload bucket

  1. In the Neon SQL Editor, run db/schema.sql against the database in DATABASE_URL.
  2. Neon is the PostgreSQL database. Uploads use a separate S3-compatible bucket; set the S3 variables in Render.
  3. Configure bucket CORS to accept PUT requests from https://rwd.2bd.net and https://flare-os.github.io, including the Content-Type header.
  4. If uploaded files should be publicly viewable, enable public reads for approved objects and set S3_PUBLIC_BASE_URL.

6 · Verify the API

Once Render marks the custom domain verified, open:

https://api.rwd.2bd.net/api/health

A healthy deployment with Neon configured returns JSON like:

{"ok":true,"service":"REWIND API","database":"connected"}

Then visit https://rwd.2bd.net and create the account lunastral. After signup, open Neon SQL Editor and grant the Owner role with UPDATE users SET role = 'owner' WHERE username_key = 'lunastral';. Then log out and back in so the admin panel picks up the new role.

  • Render deploy is live and the health check passes.
  • Render shows api.rwd.2bd.net as verified and HTTPS is active.
  • The API health response says database: connected.
  • The main website at rwd.2bd.net still loads as before.

Free-plan behavior

Render's free web services sleep after 15 minutes without incoming requests. The next request wakes the service, which can take about a minute. This is fine for testing, but means the first login or API request after a quiet period may feel slow. Render also documents monthly instance-hour and bandwidth limits. Render free-service limits ↗

Troubleshooting

Render's Verify button fails

Check the CNAME name is api within the RWD.2BD.NET zone, and the target exactly matches the service's .onrender.com hostname. Remove any conflicting A, AAAA, or other CNAME record for the api host only, then wait and retry.

The health check fails

Check the Render deploy logs and confirm environment variables are set. Verify DATABASE_URL is correct and run db/schema.sql in the matching Neon database.

The browser reports CORS errors

Set CORS_ORIGINS to the website origins exactly, with no trailing slash: https://rwd.2bd.net,https://flare-os.github.io. Confirm NODE_ENV=production, then redeploy.

The FreeDomain.one panel rejects the record

Use the host format it expects: either the full api.rwd.2bd.net. name or just api if it appends the zone automatically. If you cannot create a CNAME under your assigned zone, contact FreeDomain.one support to ask whether DNS editing for that subdomain is enabled.
