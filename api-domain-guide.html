Before you start

You need the REWIND repository pushed to GitHub and a Vercel account. GitHub Pages serves the website files; Vercel runs the Node API. Vercel's dashboard gives the exact DNS target for your project, so copy that value instead of guessing it.

Keep these two addresses separate:

ADDRESSWHAT IT SERVES
rwd.2bd.netExisting REWIND website on GitHub Pages
api.rwd.2bd.netNode API on Vercel

The REWIND API is already in the repository's api/ folder. The frontend calls https://api.rwd.2bd.net/api/… after it is deployed.

1 · Deploy the API project on Vercel

1

Import the GitHub repository

In Vercel, choose Add New → Project, connect GitHub, then import flare-OS/rwd-website.

2

Choose the project root

Set the Root Directory to the directory containing package.json, vercel.json, and the api/ folder. In this repository that is the repository root. Leave the Framework Preset as Other if Vercel asks.

3

Deploy

Click Deploy. Vercel will build the Node functions from api/. Save the Vercel project; you will add its custom domain next.

Deploying this project on Vercel does not change the GitHub Pages DNS for rwd.2bd.net. We will add only the api subdomain record.

Vercel's current dashboard flow is Project → Settings → Domains → Add Domain. Their docs: Set up a custom domain on Vercel ↗.

2 · Assign the subdomain to the Vercel project

1

Open the API project's Domains settings

In Vercel, open the project you just deployed, then select Settings → Domains.

2

Add this exact hostname

Click Add Domain, enter:

api.rwd.2bd.net

Assign it to the production environment if Vercel asks, then add it to the project.

3

Copy Vercel's DNS instructions

The domain will initially show a configuration warning. Open its details and copy the exact CNAME target Vercel displays. A target can be a project-specific hostname; use the one shown on your screen.

3 · Add one DNS record at your domain DNS provider

Open FreeDomain.one, then the DNS zone for RWD.2BD.NET—the same page where you saw the Host Records and Alias Records tables. In Alias Records (CNAME), add this row:

FREEDOMAIN.ONE FIELDVALUE
Alias / CNAME Recordapi.rwd.2bd.net.
Alias to Host[copy the exact CNAME target shown in Vercel]
TTL08:00 or the current default

Save/add the record. If the form automatically appends .rwd.2bd.net to names, enter only api as the alias. Do not include https:// in the target.

If the DNS form asks for a full host instead of a relative name, enter api.rwd.2bd.net. If it adds the zone name automatically, enter only api. The target should be the Vercel-provided hostname, not a URL: omit https:// and any path.

Do not edit the existing apex rwd.2bd.net record or the www record for this task. Add only the api CNAME. Do not create an A or AAAA record for api alongside that CNAME; a hostname cannot have both.

Save the record. Return to Vercel → Settings → Domains and click Refresh or Verify. DNS may take a while to update; keep the record in place while Vercel checks it. See Vercel's domain troubleshooting guide ↗.

4 · Add the API's environment variables in Vercel

The local .env file is ignored by Git and is not uploaded to Vercel. Enter values in Vercel → Project → Settings → Environment Variables. Add each variable to Production (and Preview/Development if you want those environments configured).

VARIABLEVALUE / PURPOSE
DATABASE_URLYour Neon PostgreSQL connection string
OWNER_USERNAMElunastral
OWNER_BOOTSTRAP_TOKENA long, private random token you choose. You will enter it once when signing up as lunastral.
CORS_ORIGINShttps://rwd.2bd.net,https://flare-os.github.io
API_PUBLIC_URLhttps://api.rwd.2bd.net
COOKIE_DOMAINLeave empty. The API cookie can stay scoped to the API host.
S3_ENDPOINTS3-compatible bucket endpoint for file uploads
S3_REGIONBucket region required by its provider
S3_BUCKETBucket name
S3_ACCESS_KEY_IDPrivate bucket access key
S3_SECRET_ACCESS_KEYPrivate bucket secret key
S3_PUBLIC_BASE_URLPublic object base URL, if the bucket serves public approved assets
Neon is used for PostgreSQL. The upload handler expects a separate S3-compatible object bucket; put that provider's credentials in these S3 variables, not in frontend code.

After adding or changing variables, trigger a new Vercel production deployment so functions use them. Never commit the token, database URL, or bucket keys to GitHub.

5 · Prepare the database and bucket

  1. In the Neon SQL Editor for your database, run the repository file db/schema.sql once to create users, sessions, places, and assets tables.
  2. In your S3-compatible bucket settings, allow browser PUT uploads from https://rwd.2bd.net and https://flare-os.github.io. Allow the Content-Type request header.
  3. If uploaded icons or catalog images should be visible to visitors, configure public reads for approved objects and set S3_PUBLIC_BASE_URL to the provider's object base URL.

The bucket and database are independent services. Uploads will report that bucket storage is not configured until the S3 variables are set.

6 · Verify the API domain

  1. Wait for Vercel's domain page to show the hostname as configured/valid.
  2. Open this address in a browser:
https://api.rwd.2bd.net/api/health

When the domain and database are configured, the response should be JSON similar to:

{"ok":true,"service":"REWIND API","database":"connected"}

Then open https://rwd.2bd.net, create an account, and sign in. To create the Owner account, use username lunastral and the private bootstrap token you set in Vercel.

  • Main website still opens at https://rwd.2bd.net.
  • Vercel marks api.rwd.2bd.net as configured and provisions HTTPS.
  • The health URL returns database: connected.
  • The API environment has your correct CORS origins and private credentials.

Troubleshooting

Vercel says “Invalid Configuration”

Compare the DNS record at your DNS provider with the exact target Vercel lists under the domain. Check that the record name is api in the rwd.2bd.net zone, and remove any conflicting A/AAAA record for that same api hostname. DNS caches can take time to refresh.

The health URL returns 404

Confirm the Vercel project root contains the REWIND api/ directory and that the latest deployment completed successfully. Inspect Vercel's deployment logs for function build errors.

The health URL returns a database error

Check that DATABASE_URL is set in Vercel Production and that db/schema.sql has been run in the matching Neon database. Redeploy after changing environment variables.

The browser reports a CORS error

Set CORS_ORIGINS exactly to the site's origins, comma-separated and without trailing slashes: https://rwd.2bd.net,https://flare-os.github.io. Save, then redeploy.

Account creation says the Owner username is reserved

Confirm OWNER_USERNAME is lunastral, set OWNER_BOOTSTRAP_TOKEN in Vercel, redeploy, then enter that same token in the signup form. The token should remain private.

Uploads fail although login works

Check all S3 variables, bucket permissions, and the bucket CORS policy. The browser upload is a direct PUT to the bucket, so the bucket must allow the website origin and Content-Type.
